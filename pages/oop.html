Think In Objects

Object-oriented programming groups data and the actions that use it. A class is a reusable design, and an object (or instance) is one real item created from that design. An attribute stores information; a method is a function that belongs to the object.

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

The class describes what every account has and can do. Each customer gets a separate object with its own owner and balance. Banking, games, online shops, and school systems use classes to model customers, players, products, and students.

Inheritance lets a new class reuse an existing class. super() calls the parent behavior. A double-underscore method such as __init__ is a dunder method, a special hook Python calls at a specific time.

Key words: class (design), instance (created object), attribute (stored data), method (object action), constructor (initial setup), inheritance (reuse from a parent), override (replace behavior), and encapsulation (protect internal details).

Classes & Objects

class Developer:
    def __init__(self, name, stack):
        self.name = name
        self.stack = stack

    def introduce(self):
        return f"Hi, I'm {self.name} and I code in {self.stack}."

# Create objects (instances)
dev1 = Developer("Javanson", "Python")
dev2 = Developer("Alice", "JavaScript")

print(dev1.introduce())
print(dev2.introduce())
Hi, I'm Javanson and I code in Python. Hi, I'm Alice and I code in JavaScript.

Inheritance

class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "Some sound"

class Dog(Animal):
    def speak(self):
        return "Woof!"

class Cat(Animal):
    def speak(self):
        return "Meow!"

dog = Dog("Rex")
cat = Cat("Whiskers")
print(dog.name, "says", dog.speak())
print(cat.name, "says", cat.speak())
Rex says Woof! Whiskers says Meow!

super() Function

class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

class Manager(Employee):
    def __init__(self, name, salary, team_size):
        super().__init__(name, salary)
        self.team_size = team_size

    def details(self):
        return f"{self.name} manages {self.team_size} people."

m = Manager("Javanson", 50000, 8)
print(m.details())
Javanson manages 8 people.

Encapsulation (Private Members)

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.__balance = balance   # Private

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount

    def get_balance(self):
        return self.__balance

acc = BankAccount("Javanson", 1000)
acc.deposit(500)
print(acc.get_balance())
1500

Dunder (Magic) Methods

Dunder means "double underscore." These methods define how an object responds to Python's built-in operations. You normally do not call them directly: Python calls __str__ when it needs readable text and calls __len__ when you use len().

class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages

    def __str__(self):
        return f"'{self.title}' ({self.pages} pages)"

    def __len__(self):
        return self.pages

b = Book("Python Mastery", 350)
print(b)
print(len(b))
'Python Mastery' (350 pages) 350

When print(b) runs, Python looks for b.__str__() and displays its returned string. When len(b) runs, Python looks for b.__len__() and expects an integer. Defining these methods makes your custom class work naturally with familiar Python syntax.

Common Errors & Bugs

TypeError: Developer.__init__() missing 1 required positional argument: 'stack'

Cause: Forgetting to pass all required arguments when creating an object.

AttributeError: 'Developer' object has no attribute 'age'

Cause: Accessing an attribute that wasn't set in __init__.
