18. Asynchronous Programming

Write fast, concurrent code with async/await.

Home / Lesson 18

Understand Async Work

Synchronous code waits for one task to finish before starting the next. Asynchronous code can pause while waiting for slow input/output, such as a network response, and let another task use that time. It is concurrency, not the same thing as running CPU work in parallel.

import asyncio

async def get_message():
    await asyncio.sleep(1)  # pretend to wait for a service
    return "Response received"

print(asyncio.run(get_message()))

async def creates a coroutine, and await pauses that coroutine until the result is ready. An event loop coordinates paused and ready tasks. Websites use this pattern for several API calls, chat servers, downloads, and other I/O-bound work.

asyncio.gather() waits for several coroutines together. Use async code when waiting dominates the work; ordinary synchronous code is often simpler for a short script or heavy CPU calculation.

Key words: coroutine (async function work), event loop (task coordinator), task (scheduled coroutine), I/O-bound (waiting on input/output), concurrency (making progress on several tasks), and asyncio (Python's async library).

Why Async?

Async lets your program do other work while waiting for I/O such as an API response or a timer. It is concurrent, not automatically parallel: one thread rapidly switches between tasks whenever the current task reaches an await.

# Sequential: about 3 seconds
    await task("A", 2)
    await task("B", 1)

    # Concurrent: about 2 seconds
    await asyncio.gather(
        task("A", 2),
        task("B", 1)
    )

In the sequential version, task B cannot start until task A finishes. In the concurrent version, both timers begin before either one finishes, so the total time is close to the longest wait, not the sum of all waits. Async is most useful when the program spends much of its time waiting; it does not make a CPU-heavy calculation faster by itself.

Basic async / await

import asyncio

async def greet(name):
    print(f"Hello {name}...")
    await asyncio.sleep(1)
    print(f"Goodbye {name}")

asyncio.run(greet("Javanson"))
Hello Javanson... (1 second pause) Goodbye Javanson

Running Tasks Concurrently

import asyncio

async def task(name, delay):
    await asyncio.sleep(delay)
    print(f"Task {name} done after {delay}s")

async def main():
    await asyncio.gather(
        task("A", 2),
        task("B", 1),
        task("C", 3)
    )

asyncio.run(main())
Task B done after 1s Task A done after 2s Task C done after 3s (all finish in ~3s, not 6s)

task(...) creates coroutine objects. asyncio.gather() schedules them together and returns their results in the same order they were supplied, even though the messages finish in delay order. The event loop resumes whichever task is ready, which is why task B prints first.

Real-World Example: Fetching URLs

import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as response:
        return await response.text()

async def main():
    urls = [
        "https://python.org",
        "https://w3schools.com",
        "https://realpython.com"
    ]
    async with aiohttp.ClientSession() as session:
        tasks = [fetch(session, url) for url in urls]
        results = await asyncio.gather(*tasks)
        for url, html in zip(urls, results):
            print(f"{url}: {len(html)} bytes")

# asyncio.run(main())

Install the third-party client before running this example with python -m pip install aiohttp. A single ClientSession is shared by all requests so connections can be reused. In production code, add a timeout and catch network errors because a server may be slow or unavailable.

Common Errors & Bugs

RuntimeWarning: coroutine 'greet' was never awaited

Cause: Calling an async function without await or asyncio.run().

RuntimeError: asyncio.run() cannot be called from a running event loop

Cause: Trying to call asyncio.run() inside an already-running loop (e.g., Jupyter). Use await main() instead.
