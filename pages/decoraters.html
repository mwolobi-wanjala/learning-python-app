17. Decorators & Generators

Supercharge your functions with higher-order magic.

Home / Lesson 17

Understand Decorators and Generators

A decorator is a function that adds behavior to another function without editing its original body. A decorator receives a function, creates a wrapper, and returns the enhanced function. The @name syntax applies that decorator.

def log_call(function):
    def wrapper():
        print("Starting")
        function()
        print("Finished")
    return wrapper

@log_call
def greet():
    print("Hello")

Python evaluates @log_call when the function is created. It is equivalent to writing greet = log_call(greet), so the name greet now refers to wrapper. When you call greet(), the wrapper prints Starting, calls the original function through function(), and then prints Finished.

Real decorators should usually accept *args and **kwargs so they work with functions that receive different arguments. Use functools.wraps inside the wrapper to preserve the original function's name and documentation. Web frameworks use decorators for login checks, permissions, routes, and timing because the same extra behavior can surround many functions.

A generator produces one value at a time with yield instead of building every value in memory. This is called lazy evaluation and is useful for large files, database rows, or streams of incoming data.

Key words: decorator (behavior added around a function), wrapper (replacement function), callable (something that can be called), generator (one-at-a-time producer), yield (pause and produce), and lazy evaluation (wait until a value is needed).

What is a Decorator?

A decorator is a function that wraps another function to add extra behavior without changing its code.

def my_decorator(func):
    def wrapper():
        print("Before function runs")
        func()
        print("After function runs")
    return wrapper

@my_decorator
def say_hello():
    print("Hello, JANS TECH!")

say_hello()
Before function runs Hello, JANS TECH! After function runs

The function is not changed internally. The decorator controls what happens before and after it, which keeps the business logic in say_hello() separate from logging or access-control logic.

Practical Decorator: Timer

import time

def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f"{func.__name__} took {end - start:.4f}s")
        return result
    return wrapper

@timer
def slow_add(a, b):
    time.sleep(1)
    return a + b

print(slow_add(3, 5))
slow_add took 1.0013s 8

Generators

Generators produce values lazily using yield, saving memory.

def count_up_to(n):
    i = 1
    while i <= n:
        yield i
        i += 1

for num in count_up_to(5):
    print(num)
1 2 3 4 5

At the first call to next(), Python runs until it reaches yield, returns that value, and pauses while remembering the value of i. The next call resumes immediately after yield. After the final value, the generator raises StopIteration; a for loop catches that signal automatically.

Generator Expressions

# List comprehension - builds entire list
squares_list = [x**2 for x in range(10)]

# Generator expression - lazy
squares_gen = (x**2 for x in range(10))

print(squares_list)
print(squares_gen)
print(list(squares_gen))
[0, 1, 4, 9, 16, 25, 36, 49, 64, 81] <generator object <genexpr> at 0x...> [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]

The list comprehension creates all ten numbers immediately. The generator expression creates only a small generator object and calculates each square when it is requested. A generator is single-use, so after list(squares_gen) consumes it, another loop over it produces no values.

Common Errors & Bugs

TypeError: 'NoneType' object is not callable

Cause: Forgetting to return the wrapper function from the decorator.

TypeError: 'generator' object is not subscriptable

Cause: Trying to use indexing on a generator. Convert to list first: list(gen).
