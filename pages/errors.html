14. Errors & Debugging

Handle exceptions gracefully and squash bugs like a professional.

Home / Lesson 14

Understand Errors Before Handling Them

An exception is Python's way of reporting that something unexpected happened, such as invalid input or a missing file. The program creates a traceback, which points toward the line where the problem occurred. try lets you attempt risky work and except gives the program a planned response.

try:
    age = int(input("Age: "))
except ValueError:
    print("Please enter a whole number.")

If the user types letters, Python raises ValueError; the handler displays a helpful message instead of crashing. Forms, payment systems, file imports, and network requests use this pattern because users and services do not always provide perfect data.

else runs when no error occurred, finally runs whether an error occurred or not, and raise lets your code report an invalid situation deliberately. A debugger and breakpoint pause execution so you can inspect values rather than guessing.

Key words: exception (runtime problem), handler (code that responds), traceback (error path), raise (create an exception), breakpoint (pause location), and debugger (tool for inspecting a running program).

try / except

Prevent your program from crashing when something goes wrong.

try:
    num = int(input("Enter a number: "))
    result = 100 / num
    print(f"Result: {result}")
except ValueError:
    print("That's not a valid number!")
except ZeroDivisionError:
    print("Cannot divide by zero!")
except Exception as e:
    print(f"Something went wrong: {e}")
Enter a number: 0 Cannot divide by zero!

try / except / else / finally

try:
    file = open("data.txt", "r")
    content = file.read()
except FileNotFoundError:
    print("File not found!")
else:
    print("File read successfully")
    print(content)
finally:
    print("This always runs")
File not found! This always runs

Raising Exceptions

def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative!")
    return age

try:
    set_age(-5)
except ValueError as e:
    print(f"Error: {e}")
Error: Age cannot be negative!

Custom Exceptions and Chaining

Create a custom exception when callers need to distinguish one business rule from other errors. Use raise ... from error when a lower-level failure should keep its cause.

class InsufficientFundsError(Exception):
    pass

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError("Balance is too low")
    return balance - amount

try:
    print(withdraw(100, 150))
except InsufficientFundsError as error:
    print(f"Payment declined: {error}")
Payment declined: Balance is too low

Catch the narrowest exception you can handle. Avoid hiding programming errors with a broad except Exception unless you log the error and have a deliberate recovery plan.
